# GeoWAN Console v0.5.0 设计范围

## 目标

在 v0.4.0 实机验收通过的只读控制台基础上，增加攻击来源画像、ASN 观察画像和来源关联线索。重点从“统计有哪些来源”提升到“单个来源表现出什么行为、不同来源之间有哪些可验证的共同特征”。

## 兼容性与安全边界

- 基于 `feature/geowan-console-v0.4.0`。
- 继续兼容 OpenWrt 25.12.x、firewall4、nftables、现有 LuCI/rpcd。
- 只读 SQLite 查询；不改变现有 nftables 规则、集合、计数器、DNAT、PPPoE、daed 或代理分流。
- 不新增 TCP/UDP 监听端口，不引入 Node/npm、Docker 或外部 Web 服务。
- 不增加写入型 rpcd 方法，不提供手动封禁/解封或自动封禁。
- 优先复用现有 `events`、`bans`、`geoip_cache` 表；本版本不做 SQLite schema migration。
- 不调用逐 IP 公网查询 API，不上传路由器日志或 IP 数据。
- 所有新查询必须有严格参数校验、固定时间范围、LIMIT 上限和只读数据库连接。

## 功能范围

### 1. 来源 IP 画像

输入或从来源排行点击一个 IP，展示：

- GeoIP 国家、地区/城市、ASN 和网络组织（明确标注为 DB-IP Lite 网络归属估算）。
- 指定时间范围内的日志样本数、首次/最近样本时间。
- 不同目标 IP、目标端口、协议的分布。
- 活跃时间桶、最近采样事件。
- 若该 IP 当前存在动态黑名单记录，展示当前剩余 TTL；没有记录时不推断其被封禁。
- 透明的本地行为观察评分和构成项。

### 2. ASN / 网络组织画像

选择 ASN 后展示：

- 来源 IP 数、日志样本数、每来源平均样本数。
- 国家/地区、目标端口、协议分布。
- 样本最多的来源 IP。
- 不同来源 IP 是否在相近时间命中相同目标 IP、端口和协议的关联线索。

ASN 归属本身不代表恶意。大型云厂商、CDN、VPN 和托管网络可能有大量不同客户；不得仅按 ASN 名称或来源数量将其标记为恶意。

### 3. 来源关联线索

只输出可解释的共同特征，例如：

- 同一 ASN 的多个来源 IP 在相近时间命中同一目标 IP/端口/协议。
- 不同 ASN 的来源 IP 在相近时间命中相同目标服务。
- 关联簇的时间窗口、来源 IP 数、样本数和代表性来源。

界面使用“关联线索”“共同观测特征”等措辞，不将其表述为同一攻击者、同一组织或已确认的攻击活动。

### 4. 观察评分

评分仅描述本机已采集日志中的行为强度，不是威胁情报信誉分，也不直接触发防火墙动作。

- 显示总分、等级和可解释的分项。
- 分项只能来自可复核的本地证据，例如重复样本、目标端口多样性、目标地址多样性、跨时间桶重复出现、最近活动时间。
- 不把国家、城市、ASN 名称或云厂商身份作为恶意证据。
- 数据不足时显示“证据不足”，不得强行给出高/低风险结论。
- 每处评分都注明内核日志限速和 30 天采样保留的影响。

## 建议的 RPC

所有方法均只读，具体参数和响应在实现时固定并测试：

- `source_profile`: `ip` + `period`（1h/24h/7d/30d）。
- `asn_profile`: `asn` + `period`（1h/24h/7d/30d）。
- `correlations`: `period` + 有界阈值/分页参数；只返回达到最小来源数的共同观测簇。

## 性能要求

- 所有返回数组均设上限；单次响应避免返回完整 30 天事件明细。
- 先验证 SQL 查询计划与现有索引；如确需索引，单独评估写入/迁移风险，不在本版本暗中修改生产数据库。
- 查询失败应返回稳定错误码，不能影响现有监控采集进程。
- 不对每个活跃封禁 IP 做逐条 MMDB 打开或网络请求；复用现有 GeoIP 缓存。

## 验收标准

1. 旧版 `lookup`、`list_bans`、`get_ban`、`analytics` 行为不回归。
2. 新 RPC 对无效 IP、私有 IP、无效 ASN、非法 period、超界参数和缺失数据库均安全处理。
3. 查询结果与直接 SQLite 聚合核对一致；空数据、未命中 GeoIP 和过期封禁均有明确状态。
4. 来源画像、ASN 画像和关联线索均可从 LuCI 正常访问，页面刷新不会覆盖用户当前选择。
5. Python 单元测试、语法检查、rpcd list/call 协议检查全部通过。
6. 在目标 OpenWrt 实机完成只读预检、安装、功能和资源占用验收。
7. 安装/升级不修改现有防火墙规则、不新增监听端口、不改变代理分流。

## 版本边界

v0.5.0 只做分析和可解释的观察，不做自动防护。自动告警或防护动作应作为后续独立版本设计，并单独验收。
