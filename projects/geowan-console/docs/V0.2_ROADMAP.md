# GeoWAN Console v0.2 Roadmap

## Scope

v0.2 combines two user requirements:

1. Reduce visibility latency for new blocked IPs and firewall counters.
2. Add offline IP geolocation enrichment (country, subdivision/city where available, ASN and network organization).

The existing nftables enforcement remains the security boundary. Telemetry and GeoIP enrichment must never be in the packet path and must never change firewall rules, DNAT, PPPoE, VPN or proxy routing.

## Release sequence

### M1 — Fast telemetry (v0.2.0) — implemented in the development branch
- Keep the existing five-minute reconciliation/restore task as a safety net.
- Add a supervised procd monitor process.
- Sample nftables counters every five seconds.
- Inventory dynamic blacklist sets every fifteen seconds.
- Scan the bounded system log buffer every fifteen seconds and deduplicate events.
- Upsert only new IPs or meaningful expiry changes; do not rewrite all 20k+ rows on every cycle.
- Publish the existing status JSON atomically and expose collector cadence/last inventory timestamps.
- Refresh the LuCI view every five seconds.
- Use the same short-lived collector lock as the reconciliation task to avoid overlapping writes.
- Keep the old dashboard fields compatible.

Acceptance:
- New/changed blacklist entries are normally visible within 30 seconds.
- Counter display refreshes within 10 seconds.
- Cron reconciliation continues to work.
- No nftables rule, set, DNAT or listener is modified by the monitor.
- Unit tests cover unchanged expiry, refreshed expiry, new entries and lock contention.

### M2 — Offline GeoIP (v0.2.1) — initial implementation added
- Add a provider abstraction around local MMDB databases.
- Initial provider: DB-IP Lite MMDB (Country, City, ASN) with required attribution; allow MaxMind GeoLite2 as an alternative provider.
- No per-IP public API requests.
- Cache country code/name, region, city, ASN number, ASN organization, provider and database version.
- Resolve IPs lazily when first observed, then backfill existing active bans in bounded batches.
- Handle IPv4, IPv6, private/reserved, unknown and missing database cases explicitly.
- GeoIP failures must not stop collection or enforcement.

Acceptance:
- Unit tests use tiny synthetic/fake reader fixtures or a mocked reader; no real IP location is inferred in tests.
- Missing/corrupt database degrades enrichment only.
- Attribution and database version are visible in LuCI.

### M3 — LuCI intelligence views (v0.2.2) — initial query panel implemented
- Overview: counters, active bans, collector freshness and sampled-event caveat.
- Country/region/ASN rankings with clear distinction between unique blocked IPs and sampled log events.
- Initial arbitrary-IP query panel with country/city/ASN through a read-only rpcd executable plugin; searchable blacklist detail with first/last observation and remaining ban TTL remains follow-up work.
- 24h/7d/30d aggregates and paginated tables.
- No new HTTP listener; continue using LuCI/rpcd ACL and local status/API files.

### M4 — Updates, recovery and hardening (v0.2.3)
- Download GeoIP database over HTTPS to a temporary path.
- Verify expected format, size and checksum where the provider publishes one; only then atomically replace.
- Keep previous known-good database and rollback on failure.
- Track provider, release date, fetch time and checksum.
- Test full reboot recovery separately from firewall reload persistence.
- Add DB backup/migration rollback, bounded retention and resource/performance tests.

## Data and privacy

- Keep SQLite and MMDB under root-owned directories with restrictive permissions.
- Never upload IP telemetry or user-specific databases to GitHub.
- Dashboard stays LAN/VPN-only.
- GeoIP describes registered network allocation, not a person's exact physical location.
- Sampled kernel logs are not a complete count of all packets; nftables counters are aggregate counters for the current ruleset lifetime.

## Production rollout

- Develop and test on `feature/geowan-console-v0.2`.
- Keep v0.1 installed on the router until M1 tests pass.
- Deploy M1 in shadow/parallel observation first; do not replace the working cron reconciliation until verified.
- Apply M2/M3/M4 only after database migration, resource usage and rollback are tested.
- Never change existing WAN policy, GeoWAN nftables rules, DNAT or service ports as part of this project upgrade.


## Current branch status

- M1 fast telemetry, procd supervision, five-second dashboard refresh, incremental ban persistence and CI checks are implemented on `feature/geowan-console-v0.2`.
- Initial M2 DB-IP Lite resolver, local cache schema, bounded active-ban enrichment, country/ASN summaries, attribution and a manual staged updater are implemented.
- Not yet implemented/validated: automatic monthly scheduling, arbitrary-IP LuCI query endpoint, city/ASN provider conformance against downloaded production MMDB files, reboot recovery on the target router, and live performance measurements.
- The updater is intentionally manual; no GeoIP download or scheduled update runs during install.

- Initial LuCI lookup now uses the authenticated rpcd `geowan.lookup` method; it reads the local cache or MMDB and adds no HTTP listener.
